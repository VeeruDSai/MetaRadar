# Plan 05-01: Stakeholder Calibration Service, WORM Feedback API & Contract Synchronization

<objective>
Implement the persistent `StakeholderCalibrationService` and FastAPI feedback/calibration endpoints (`POST /api/v1/feedback`, `GET /api/v1/feedback/summary`, `POST /api/v1/calibrate`, `GET /api/v1/calibration/weights`, `POST /api/v1/watch-items/confirm`). Deliver bounded batch weight recalibration ($\Delta w = \alpha(\overline{R} - 3.0)$ with $\alpha=0.05$ clamped to $[0.1, 2.0]$), immutable baseline routing preservation in `signal_routing`, a deterministic heuristic keyword watch-rule parser, and OpenAPI/TypeScript contract synchronization.
</objective>

<must_haves>
- `StakeholderCalibrationService` in `backend/app/services/calibration.py` manages append-only WORM `calibration_feedback`, `scoring_weights`, `calibration_history`, and `signal_routing` updates.
- Weight recalibration math follows bounded updates: $\alpha=0.05$, center baseline at 3.0, clamped to $[0.1, 2.0]$.
- Priority recomputes using calibrated weights: $\text{Priority} = w_{\text{impact}} \cdot S_{\text{impact}} + w_{\text{urgency}} \cdot S_{\text{urgency}} + w_{\text{novelty}} \cdot S_{\text{novelty}}$ without overwriting `baseline_*` fields.
- `HeuristicWatchParser` parses feedback comments deterministically for event intents (`"congress"`, `"trial"`, `"durability"`, `"regulatory"`, `"safety"`) and outputs structured `WatchRuleSuggestionSchema`.
- FastAPI endpoints registered in `backend/app/main.py` and exported cleanly to `contracts/openapi.json` and `frontend/types/api.ts` with 0 drift (`pytest tests/test_contract_drift.py`).
</must_haves>

<task id="05-01-T2">
<title>Implement StakeholderCalibrationService & Heuristic Watch Parser</title>
<read_first>
- backend/app/models/__init__.py
- backend/app/workflows/nodes/calibrate.py
- backend/app/workflows/nodes/missing_signal.py
</read_first>
<action>
Create `backend/app/services/calibration.py` with:
1. `HeuristicWatchParser`:
   - Scans text comments for keywords (`congress`, `trial`, `durability`, `regulatory`, `safety`, `competitor`).
   - Extracts structured expected event, estimated monitoring window (90, 180, or 270 days), and target responsible function.
2. `StakeholderCalibrationService`:
   - `submit_feedback(req: FeedbackSubmissionRequest)`: inserts row into `calibration_feedback`. If unapplied count for role reaches threshold $N=3$, can auto-trigger recalibration or flag ready.
   - `recalibrate_role(stakeholder_function: Optional[str] = None)`:
     - Queries unapplied feedback rows.
     - Calculates average ratings per dimension and updates `ScoringWeights` with $\alpha=0.05, \text{center}=3.0, \text{clamp}=[0.1, 2.0]$.
     - Generates next version tag `v1.{timestamp}` and inserts audit row into `calibration_history`.
     - Recalculates `calibrated_primary_function`, `calibrated_relevance_scores`, and `calibrated_suggested_action` on `signal_routing`.
     - Computes side-by-side BEFORE/AFTER comparisons and parses comments into watch rule suggestions.
   - `get_weights()`: queries active `ScoringWeights` for all 6 canonical functions (seeded with 1.0 if not present).
   - `get_summary()`: aggregates total submissions, average star ratings, and action approval rates grouped by role.
   - `confirm_watch_item(req: ConfirmWatchItemRequest)`: inserts a confirmed row into `watch_items` with status `watching`.
</action>
<verify>
`pytest tests/test_calibration_service.py -v`
</verify>
