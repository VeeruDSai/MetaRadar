# Plan 04-01: Backend Overview Extension & Database Aggregation Endpoints

<objective>
Upgrade the FastAPI backend `/api/v1/signals` and `/api/v1/overview` endpoints to query live PostgreSQL data without synthetic fallback try/except blocks (Decision D-08). Extend `/overview` with explicit Pydantic response models and set-based database aggregations (active signals, monitored assets, confluences, lifecycle development stages, and signal trend velocity per Decision D-06), synchronizing the OpenAPI contract schema.
</objective>

<must_haves>
- `backend/app/api/v1/endpoints/signals.py` must NOT catch exceptions to return hardcoded synthetic fallback dictionaries.

</must_haves>

<title>Implement Set-Based Aggregations in `/signals` and `/overview` Endpoints</title>
<read_first>

- backend/app/models/__init__.py
- backend/app/schemas/__init__.py

</read_first>
<action>
In `backend/app/api/v1/endpoints/signals.py`:
1. Remove the try/except block in `list_signals` that returned hardcoded synthetic dictionaries `{"signal_id": "sig-001", ...}`.
2. Implement set-based query on `Signal` table with pagination and deterministic ordering:
   ```python
   stmt = select(Signal).order_by(Signal.published_at.desc().nullslast(), Signal.created_at.desc()).limit(limit)
   result = await db.execute(stmt)
   signals = result.scalars().all()
   total_stmt = select(func.count(Signal.signal_id))
   total_res = await db.execute(total_stmt)
   total = total_res.scalar() or 0
   return SignalListResponse(signals=[s.__dict__ for s in signals], total=total)
   ```
3. Update `get_overview` to accept `db: AsyncSession = Depends(get_db)` and perform set-based live aggregations:
   - Query total signal count (`func.count(Signal.signal_id)`)
   - Query monitored assets count (`func.count(Asset.asset_id)`)
   - Query confluences count (`func.count(Confluence.confluence_id)`)
   - Query developments grouped by `current_stage` to populate `lifecycle` summaries
   - Return structured `OverviewResponse`.
</action>
