# Plan 06-02: Feature Parity Manifest, Parity Matrix Generator, Next.js Intelligence Pages & UI Synchronization

<objective>
Construct the structured feature parity manifest and generator script producing `docs/FEATURE_PARITY_MATRIX.md` per D-08, D-09, and D-10, add automated parity tests against the OpenAPI contract, implement the four new intelligence pages (`ConfluencePage`, `LifecyclePage`, `RedTeamPage`, `MissingSignalsPage`) per D-01, replace four placeholder pages (`DevelopmentsPage`, `FunctionsPage`, `SourcesPage`, `SettingsPage`) per D-02 and D-03, wire cleanly mapped controls per D-05, and update the section router in Next.js 16.
</objective>

<review_incorporation>
Incorporated findings from 06-REVIEWS.md:
1. **SSR Hydration Guard on Theme Toggle:** In `SettingsPage`, implement a `mounted` state guard (`const [mounted, setMounted] = useState(false); useEffect(() => setMounted(true), [])`) to ensure `localStorage.getItem('theme')` checks only execute client-side, avoiding React 19 hydration mismatch warnings.
2. **Responsive Filter Drawer:** Ensure `FilterBar` framer-motion height animations use `overflow: hidden` and render cleanly across desktop, tablet (≤900px), and mobile (≤560px) breakpoints without viewport clipping.
</review_incorporation>

<threat_model>
ASVS Level 1 Threat Assessment:
- **T-06-04 (Fabricated Telemetry & Fake Controls):** Mocking or hardcoding UI values violating AGENTS.md honesty rules. Mitigation: All components consume real `useLiveData` hook from live backend endpoints (`/confluence`, `/lifecycles`, `/red-team`, `/missing-signals`, `/developments`, `/sources`, `/health/connectors`); honest empty states rendered when DB has 0 rows.
- **T-06-05 (Cross-Site Scripting / Untrusted HTML Injection in Excerpts):** Rendering raw signal/evidence excerpts in drawers and contradiction cards. Mitigation: React standard JSX text node rendering (safe auto-escaping); avoid `dangerouslySetInnerHTML`.
</threat_model>

<must_haves>
- **D-01:** Build the four new intelligence pages for real — Confluence Alerts (`/confluence`), Lifecycle Timelines (`/lifecycles`), Red-Team Contradictions (`/red-team`), Missing Signals (`/missing-signals`) — backed by existing DB tables (`Confluence`, `LifecycleEvent`, `Contradiction`, `WatchItem`, `Evidence`).
- **D-02:** All five GenericPage placeholders get real content — Developments, Functions, Sources, Settings — alongside the new doc pages. Calibrate stays as the Phase 5 feedback-widget context.
- **D-03:** Sources renders a real source registry from `sources` table + live `/health/connectors` status. Settings renders honest workspace controls only (dark mode, polling interval, cache clear) with no fake toggles.
- **D-05:** Wire controls that map cleanly to existing or cheap new endpoints (Apply Filter → `/signals` filters, Evidence-chain expand → evidence read, Refresh → existing polling).
- **D-08:** Deliver `docs/FEATURE_PARITY_MATRIX.md` for humans and an automated contract-parity test in `tests/test_parity_matrix.py`.
- **D-09:** Matrix uses columns `Doc spec` → `Control/feature` → `Component` → `Endpoint` → `Status`, and status vocabulary: `WIRED`, `PARTIAL`, `NOT_WIRED`, `DEFERRED`.
- **D-10:** Matrix is generated from structured manifest `docs/manifests/feature_parity_manifest.json` via `scripts/generate_parity_matrix.py`.
- `pnpm --prefix frontend run build` and `pnpm --prefix frontend run lint` exit with 0 errors.
</must_haves>
