# Plan 06-01: Backend Intelligence Reads, Signal Filters, Cache Flush API & Contract Export

<objective>
Implement the backend read-only aggregation endpoints for the four intelligence areas (`GET /api/v1/confluence`, `GET /api/v1/lifecycles`, `GET /api/v1/red-team`, `GET /api/v1/missing-signals`) and two registry areas (`GET /api/v1/developments`, `GET /api/v1/sources`) per D-04, add server-side multi-parameter filtering to `GET /api/v1/signals` per D-06, provide a Redis cache invalidation endpoint (`POST /api/v1/cache/clear`) per D-07, and synchronize the OpenAPI 3.1 contract and generated TypeScript types.
</objective>

<threat_model>
ASVS Level 1 Threat Assessment:
- **T-06-01 (SQL Injection / Data Leakage via Filters):** Untrusted query parameters passed to `GET /signals` could lead to unindexed full-table scans or injection if unparameterized. Mitigation: Use typed Pydantic parameters with parameterized SQLAlchemy `select().where()` clauses and constrained `limit=Query(50, ge=1, le=200)`.
- **T-06-02 (Cache Flush Abuse / Denial of Service):** `POST /api/v1/cache/clear` could be hammered to cause Redis thrashing. Mitigation: Dedicated endpoint with bounded cache key eviction or namespace generation bumping; return deterministic success payload `{ "status": "cleared", "timestamp": "..." }`.
- **T-06-03 (Contract Drift & Type Mismatch):** Frontend/backend out-of-sync causing runtime deserialization crashes. Mitigation: Enforce `scripts/export_openapi.py` regeneration and verify with `pytest tests/test_contract_drift.py`.
</threat_model>

<must_haves>
- **D-04:** Add honest read-only endpoints for confluence, lifecycles, red-team, missing-signals, developments, and sources in `backend/app/api/v1/endpoints/intelligence.py` and `registry.py`, backed by existing PostgreSQL tables (`Confluence`, `LifecycleEvent`, `Contradiction`, `WatchItem`, `Evidence`, `Development`, `Source`).
- **D-06:** Extend `GET /api/v1/signals` in `backend/app/api/v1/endpoints/signals.py` with optional server-side filter query params: `severity`/`priority`, `entity`/`asset`, `date_from`, `date_to`, `signal_type`, `source`, `limit`, `offset`.
- **D-07:** Implement real cache-clear endpoint `POST /api/v1/cache/clear` in `backend/app/api/v1/endpoints/cache.py` that flushes Redis cache keys / bumps cache version and returns honest status without fabricated claims.
- `scripts/export_openapi.py` exports `contracts/openapi.json` and updates `frontend/types/api.ts` cleanly with 0 drift (`pytest tests/test_contract_drift.py`).
- `pytest tests/test_contract_drift.py` and `pytest tests/test_api_endpoints.py` pass 100%.
</must_haves>
