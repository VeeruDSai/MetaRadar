# Plan 04-03: Real-Time Workspace UI Wiring, Search Dialog & Honest Telemetry

<objective>
Wire the Next.js presentation components in `frontend/components/metaradar.tsx` to live backend data via `useLiveData`. Render dynamic signals with severity filters, evidence drawers, and real empty states (Decision D-09); implement the Ask Athena synthesis UI with error resilience (REQ-P4-3); integrate the ⌘K semantic vector search dialog with `POST /api/v1/search`; de-label all synthetic demo text (Decision D-10); and wire live telemetry & degraded health alerts (Decisions D-10, D-12) to `/health/ready` and `/health/models`.
</objective>

<must_haves>
- `DashboardPage` and `SignalsPage` must consume live data from `useLiveData(getOverview)` with auto-refreshing 30s polling.
- `SignalsPage` renders live severity filtering (`all`, `critical`, `high`, `medium`, `low`), dynamic signal count statistics, and opens the `SignalDrawer` with real signal provenance and four-question breakdown.
- `IntelligencePage` connects `askAthena` directly to `/api/v1/athena` with interactive state, confidence indicator, evidence count, and graceful error/rejection handling (REQ-P4-3).
- Topbar "Search signals" button and `⌘K`/`Ctrl+K` keyboard shortcut open an accessible search modal executing `searchSignals` against `POST /api/v1/search` with keyboard navigation and Escape dismissal.
- Sidebar "Synthetic signal environment" and footer "Demo environment · Synthetic data" labels are replaced with honest live system telemetry and dynamic model metadata (Decision D-10).
- Degraded health status (`/health/ready` reporting `"degraded"`) surfaces an amber non-blocking notification banner (Decision D-12).
- Zero TypeScript (`tsc`) errors and clean Next.js build (`npm run build`).
</must_haves>

</action>
