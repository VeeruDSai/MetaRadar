# Plan 06-03: Automated Zero-Config setup.py & Production-Grade start.py Process Launcher

<objective>
Implement the zero-config automated setup script `setup.py` per D-11 and D-12 (Docker Compose services, environment file creation, database migrations with readiness polling, synthetic dataset seeding, and Ollama model verification with `--skip-models`), the unified production-grade process launcher `start.py` per D-13, D-14, and D-15 (host FastAPI backend, host Next.js frontend, Docker dependencies, live terminal health monitoring table, robust cross-platform subprocess tree termination, no Celery, GPU/CPU fallback, and graceful SIGTERM shutdown), and perform full end-to-end Definition of Done verification.
</objective>

<review_incorporation>
Incorporated findings from 06-REVIEWS.md:
1. **Cross-Platform Process Subtree Teardown:** In `start.py`, implement `terminate_process_tree(proc)`: on Windows invoke `taskkill /F /T /PID <pid>` to terminate child Node.js and Python Uvicorn workers spawned by shell commands; on POSIX use `os.killpg(os.getpgid(proc.pid), signal.SIGTERM)`. Prevents zombie port locks on 3000/8000.
2. **PostgreSQL Readiness Polling in setup.py:** In `setup.py`, after `docker compose up -d`, poll `pg_isready` inside the postgres container (up to 15 attempts with 1s sleep) before invoking `alembic upgrade head`, preventing premature migration connection failures.
</review_incorporation>

<threat_model>
ASVS Level 1 Threat Assessment:
- **T-06-06 (Secret Leaks via Setup Scripts):** Writing hardcoded credentials or committed secrets into generated `.env` files. Mitigation: Copy default values strictly from `.env.example` if `.env` does not exist; never overwrite existing `.env` files with private user API keys without prompt/confirmation.
- **T-06-07 (Orphaned Child Processes / Port Zombie Locks):** Abnormal script termination leaving FastAPI or Next.js running in background and locking ports 8000/3000. Mitigation: `start.py` registers signal handlers (`SIGINT`, `SIGTERM`, `atexit`) that invoke `terminate_process_tree()` to ensure full process group destruction.
</threat_model>

<must_haves>
- **D-11:** `setup.py` is compose-driven: zero-config setup runs `docker compose up -d postgres redis ollama`, polls database readiness (`pg_isready`), applies Alembic migrations (`alembic upgrade head`), seeds synthetic signals dataset (`data/synthetic_signals.json`), and creates `.env` from `.env.example`.
- **D-12:** `setup.py` auto-pulls `OLLAMA_MODEL` (`gemma3:4b`), providing a `--skip-models` flag to bypass multi-GB download on systems with cached weights.
- **D-13:** `start.py` starts compose DBs (`postgres`, `redis`, `ollama`) and host processes (`uvicorn` backend, `next dev` frontend). No Celery is launched (APScheduler runs in-process).
- **D-14:** `start.py` captures child process logs to `logs/*.log` (`logs/backend.log`, `logs/frontend.log`), runs a health polling loop (`/health/ready`, `/health/models`, frontend `/`), and renders a live status table in the terminal. Ctrl+C gracefully stops children via SIGTERM / `taskkill`.
- **D-15:** Backend runs on host with GPU/CPU support; if GPU init fails, start.py reports the honest `/health/models` state with provider fallback without fabricated health.
- Comprehensive end-to-end verification passing all testing gates (`pytest tests/ -v`, `pnpm --prefix frontend run build`, `pnpm --prefix frontend run lint`).
</must_haves>
