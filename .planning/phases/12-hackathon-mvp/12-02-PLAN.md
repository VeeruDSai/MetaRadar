# Plan 12-02: Approval Request Workflow - Backend

**Phase:** Phase 12 - Hackathon MVP
**Wave:** 2 of 4 - P1 (Cross-Functional Decision Chain)

---

## 1. Objective

Build the backend for a cross-functional approval request workflow so that:
- Non-leadership roles (Medical Affairs, Regulatory, Safety, Market Access, Communications) can request Leadership approval for a critical signal
- Leadership can view all pending approval requests and approve or reject each with a decision note
- All approval actions are recorded in audit_log

This directly implements the mentor's requirement: "high-impact signals escalated to Leadership"
and earns rubric points for Cross-Functional Usefulness (10 pts) and Compliance/Governance (10 pts).

  CREATE TABLE approval_requests (
    request_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

### D. [MODIFY] backend/app/api/v1/endpoints/signals.py

Add three new endpoints:

POST /signals/{signal_id}/request-approval
  - Allowed roles: MEDICAL_AFFAIRS, REGULATORY, SAFETY, MARKET_ACCESS, COMMUNICATIONS
  - Body: ApprovalRequestCreate
  - Creates ApprovalRequest row (status=PENDING)
  - Creates AuditLog entry (action=APPROVAL_REQUESTED)
  - Returns: ApprovalRequestSchema

GET /signals/pending-approvals
  - Allowed roles: LEADERSHIP, ADMIN only (403 for others)
  - Returns: List[ApprovalRequestSchema] where status=PENDING
  - Includes signal title, priority, source for quick triage

POST /signals/{signal_id}/resolve-approval
  - Allowed roles: LEADERSHIP, ADMIN only (403 for others)
  - Body: ApprovalRequestResolve (status: APPROVED | REJECTED, resolution_note)
  - Updates ApprovalRequest: status, resolved_by_user_id, resolved_by_role, resolution_note, resolved_at=now()
  - Creates AuditLog entry (action=APPROVAL_RESOLVED)
  - Returns: ApprovalRequestSchema

### E. [MODIFY] backend/app/schemas/__init__.py - Extend SignalSchema

Add approval_status Optional[str] and latest_approval_request Optional[ApprovalRequestSchema]
to SignalSchema so the frontend can render the approval badge on the signal card.

Update _serialize_signal() in signals.py to query latest approval_request for each signal
and include it in the response (with a LEFT JOIN or separate query).

## 3. Test File: tests/test_approval_workflow.py

Scenarios:
1. Medical Affairs requests approval on a HIGH signal -> 200 OK, PENDING status
2. Safety requests approval on a CRITICAL signal -> 200 OK, PENDING status
3. Communications (invalid role for leadership request resolution) requests approval -> 200 OK (requesting is allowed)
4. Medical Affairs CANNOT resolve approvals -> 403 Forbidden
5. Leadership resolves approval as APPROVED -> 200 OK, status=APPROVED, resolved_by_role=LEADERSHIP
6. Leadership resolves approval as REJECTED -> 200 OK, status=REJECTED
7. GET /pending-approvals as LEADERSHIP -> returns PENDING records
8. GET /pending-approvals as MEDICAL_AFFAIRS -> 403 Forbidden
9. AuditLog has APPROVAL_REQUESTED entry after request
10. AuditLog has APPROVAL_RESOLVED entry after resolution
11. SignalSchema includes approval_status after request
12. E2E: Medical Affairs requests -> Leadership approves -> Medical Affairs sees APPROVED badge
