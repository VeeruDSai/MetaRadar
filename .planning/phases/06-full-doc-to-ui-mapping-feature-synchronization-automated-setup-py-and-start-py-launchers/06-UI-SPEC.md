## Interaction Specifications

### Apply Filter (Signals page — D-06)

| Element | Spec |
|---------|------|
| Filter trigger | "Filters" button in signals toolbar (lucide SlidersHorizontal icon + label) |
| Filter panel | Inline expansion below toolbar — framer-motion height animation, not a modal |
| Controls inside | severity multi-select chips, entity/asset text input, date-range from/to, signal_type select, source select |
| Apply button | Filled accent button — "Apply Filters" — triggers GET /signals with params; disabled while fetch in-flight |
| Clear button | Ghost button — "Clear" — resets all filters, refetches unfiltered |
| Loading state | Signals list shows 3 skeleton rows while fetch is in-flight; toolbar shows RefreshCw spinner |
| Empty state | "No signals match these filters" + Clear button (honest, no fabricated fallback data) |

### Cache Clear Modal (D-07)

| Element | Spec |
|---------|------|
| Trigger | "Clear Cache" button in Settings page — danger-toned outline button |
| Modal | @base-ui/react Dialog; 420px wide; centered; backdrop blur |
| Heading | "Clear Server Cache" |
| Body | "This will flush the Redis cache. Live data will be re-fetched on next request. This action cannot be undone." |
| Confirm button | Filled danger button — "Clear Cache" — calls POST /api/v1/cache/clear; loading spinner on click |
| Cancel button | Ghost button — "Cancel" |
| Success toast | In-page toast: var(--success) tint, "Cache cleared — data will refresh on next request" |
| Error toast | In-page toast: var(--danger) tint, honest error message from API |
| Honest behavior | No fabricated "refreshed X items" claim; toast is fixed wording independent of cache size |

### Sources Page — /health/connectors integration

| Element | Spec |
|---------|------|
| Status indicators | Per-source badge: LIVE (success), DEGRADED (warning), DOWN (danger), UNKNOWN (muted) |
| Freshness badge | Source freshness label: real-time / near-real-time / delayed / batch / adapter-ready / synthetic |
| Last synced | Relative timestamp (e.g., "3h ago") from connector health payload |
| Honest failures | A failed optional source shows DEGRADED — never removes the row |
| Refresh | Polls /health/connectors at same interval as useLiveData (30s, visibility-aware) |

### Settings Page

| Element | Spec |
|---------|------|
| Dark mode toggle | Switch — applies/removes .dark class on html; persisted to localStorage |
| Polling interval | Select: 15s / 30s / 60s / 5min — updates useLiveData interval via context; persisted to localStorage |
| Clear Cache | Danger-toned outline button opens CacheClearModal |
| No fake controls | Every control maps to a real behavior — no placeholder toggles, no "coming soon" labels |

### New Intelligence Pages (Confluence, Lifecycle, Red-Team, Missing Signals)

| Pattern | Spec |
|---------|------|
| Page header | Page title + section description (13px muted) + KPI summary row (2-3 KPI cards) |
| Data loading | useLiveData hook — 3 skeleton rows while loading |
| Empty state | "No [confluences / timelines / contradictions / missing signals] detected" — no fabricated data |
| Error state | .error-card — "Failed to load data" + "Retry" button |
| Expandable rows | Click to expand reveals full evidence chain — framer-motion AnimatePresence height animation |
| Pagination | "Load more" button (ghost) at bottom — not infinite scroll |
| Polling | 30s auto-refresh, visibility-aware (existing useLiveData pattern) |

## Copywriting Contract

| Surface | Copy rule |
|---------|-----------|
| Empty states | "No [noun phrase] detected" — affirmative, no blame, no apology |
| Error states | "Failed to load [noun]" + "Retry" — never "Something went wrong" |
| Loading states | Skeleton rows only — no loading text |
| Cache clear confirm body | Exact: "This will flush the Redis cache. Live data will be re-fetched on next request. This action cannot be undone." |
| Cache clear success toast | Exact: "Cache cleared — data will refresh on next request." |
| Provider degraded banner | Exact (UI doc principle 19): "AI reasoning unavailable — showing source-grounded factual summary." — non-suppressible |
| WIRED / NOT_WIRED labels | WIRED / PARTIAL / NOT_WIRED / DEFERRED — consistent with D-09; never hand-wave status |
| Action buttons | Imperative verbs: "Apply Filters", "Clear Cache", "Load More", "View Evidence", "Confirm Watch" |
| Settings controls | Label first, control second; no "experimental" or "beta" labels for real controls |
